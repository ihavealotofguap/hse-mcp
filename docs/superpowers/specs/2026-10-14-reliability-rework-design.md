## 4. Ресурс

```ts
const elkSchedule = defineResource<{ from: Date; to: Date }, ElkScheduleDay[]>({
  name: "elk.schedule",          // домен "elk:" берётся из имени
  ttl: TTL.medium,
  key: (a) => weekKey(a),        // канонический ключ, не строка пути
  load: (a, ctx) => ...,         // ctx.signal — отмена по дедлайну
  project: (raw, a) => ...,      // необязательно: срез после кэша
  deadlineMs: 45_000,            // необязательно: верхняя граница одной загрузки
});
```

Правила:
- **Один владелец ключа.** Ключ задаёт ресурс, строки `elk:/api/...` вручную не собираются.
- **Домен из имени.** `clearCache("lms:")` и `hse_clear_cache({scope})` сохраняют смысл.
- **Срез после кэша.** `limit` не входит в ключ: ресурс грузит максимум, `project` режет.
  `listMessages(10|20|50)` → один запрос (закрывает F6).
- **Дедупликация и защита от гонки с очисткой** сохраняются как в текущем `cache.ts` (поколение
  `generation`). Ошибки не кэшируются.
- **Результат только для чтения.** Типы ресурса — `DeepReadonly<T>`; мутировать общий объект
  запрещает компилятор (стоимость во время выполнения нулевая).
- **Реестр.** Каждый ресурс регистрируется по имени; реестр используется для инвалидации по имени
  и для проверки, что у ресурса есть домен и TTL.
- **Инвалидация.** `invalidates?: string[]` у будущих записывающих ресурсов (№4) сбрасывает
  перечисленные ресурсы по имени. В рамках №1 механизм реализуется и проверяется на одном
  фиктивном случае в изолированном скрипте, реальных записывающих ресурсов нет.

### 4.1 Нормализация ключей

- **Расписание ЕЛК.** Запрашивается и кэшируется **по неделям** (понедельник–воскресенье);
  `getSchedule(from, to)` собирает диапазон из недельных блоков и режет по датам. Три сводки делят
  блоки. Цена: до одного лишнего недельного запроса (прямой API ≈ 30–200 мс).
- **События календаря LMS** (`listActionEvents`). Страница + до 6 AJAX-запросов — дорогой
  ресурс. Правая граница округляется **вверх** до корзины {7, 14, 30, 60} дней от сегодня,
  `project` отсекает события позже запрошенной даты и пересчитывает `truncated`: если запрошенная
  граница раньше последнего полученного события, усечения для этого запроса нет.
  Левая граница по-прежнему дневной гранулярности.
- **Списки с `limit`** (сообщения LMS, уведомления ЕЛК, заявки, задачи): максимум в ключе нет,
  срез через `project`.

## 5. `withPage`

```ts
withPage<T>(url, fn: (page, ctx) => Promise<T>, opts?: { deadlineMs?: number }): Promise<T>
```

- Занимает слот лимитера, открывает страницу, проходит вход, вызывает `fn`, **в `finally`
  закрывает страницу и освобождает слот**. Вызывающий код `page.close()` не пишет.
- `deadlineMs` по умолчанию 45 с (подпроект 2 использует 40 с на источник; значение больше
  внешнего таймаута источника, чтобы слот не освобождался раньше, чем источник сдаётся, и не
  висел дольше разумного). По истечении `AbortSignal` отменяет ожидания внутри, страница
  закрывается, слот освобождается, `fn` получает отклонение.
- Вложенный `withPage` внутри `fn` запрещён и определяется: исключение вида «вложенное открытие
  страницы» вместо зависания (закрывает слабость, названную в исходном списке спорных решений).
- `openAuthenticatedPage` после миграции всех клиентов делается внутренним и не экспортируется.

### 5.1 Замок входа

Сейчас `withLoginLock` оборачивает весь `ensureLoggedIn`, включая ожидание рендера до 8 с на
каждой странице. Новая схема:

1. Открытие, ожидание рендера и проверка «нужен ли вход» — **вне замка**, параллельно.
2. Если вход нужен — взять замок, **повторно проверить** (другой вызов мог уже войти), при
   необходимости пройти Keycloak.
3. Критерий приёмки: из состояния с просроченной сессией N параллельных открытий дают **ровно один
   логин**; из рабочей сессии открытия не сериализуются по ожиданию рендера.

Риск: SPA, которая показывает пустую страницу и редиректит на Keycloak позже. Поэтому детектор
остаётся прежним (после `waitForRender`), меняется только область замка. Проверяется вживую (§9).

## 6. Лимитер

- Пороги **3 / 300 мс остаются** — данных об антибот-защите нет (F4 лишь подтверждает, что
  ограничение работает). Они выносятся в константы с комментарием «не измерено».
- Слот возвращается в `finally` `withPage`; **аренда** (по умолчанию `deadlineMs` + 5 с) — страховка
  от любой утечки: по истечении слот освобождается принудительно, в stderr пишется предупреждение.
- Ожидание слота получает таймаут (тот же дедлайн), чтобы очередь не копилась бесконечно (F3).
- Запросы `context.request` занимают **только интервал** между стартами (не слот): они дёшевы, но
  не должны идти без частоты.
- Межпроцессной координации нет (решение: каждый процесс сам по себе). Защищается только запись
  `storage/hse-session.json` (§7).

## 7. Токен ЕЛК, прямой путь, сессия

- **Токен.** Как сейчас: JWT, срок из `exp`, запас 30 с, параллельные запросы делят получение.
- **Политика отказов прямого пути:**
  - 401 → токен сбрасывается, один повтор со свежим токеном;
  - 403 → токен **не** сбрасывается (права, а не токен); один заход через страницу;
    если и он отказал — ошибка пользователю, прямой путь не помечается сломанным;
  - 5xx/таймаут → ошибка как есть, без отката на страницу.
- **Выключатель.** Прямой путь помечается сломанным, только если он дважды отказал, а запрос через
  страницу прошёл. Состояние открыто 10 минут, затем одна проба (half-open): удачная проба
  возвращает прямой путь, неудачная продлевает ещё на 10 минут. Заменяет необратимый
  `directApiBroken` (закрывает F2).
- **Запись сессии.** `context.storageState({ path })` пишет во временный файл рядом и
  переименовывается; незавершённая запись не ломает рабочую сессию.

## 8. Отмена по дедлайну и `digest`

- Контракт: вызов ресурса принимает необязательный `signal`; отмена вызывающего **отсоединяет**
  его от общей загрузки (его промис отклоняется), но не прерывает загрузку, пока на неё подписаны
  другие.
- Граница по времени одной загрузки — `deadlineMs` ресурса, поэтому брошенная работа не держит
  слот дольше этой границы.
- Подпроект 2 (`digest/client.ts#runSource`) может передать `AbortSignal` в клиентские функции;
  без изменений `digest` продолжает работать, получая только верхнюю границу времени загрузки.
  Правка `digest` — опциональная, в рамках миграции вызовов, не обязательная для приёмки.

## 10. Ошибки

- Ошибки загрузки не кэшируются; параллельные ожидающие получают ту же ошибку.
- Отмена по дедлайну даёт ошибку вида «`<ресурс>` не уложился в `N` с», слот освобождён.
- Ошибки политики прямого пути содержат статус и причину без токена и без query.

## 13. Риски

- **Узкий замок входа** — единственное изменение, способное сломать вход в редких состояниях;
  поэтому проверка вживую обязательна, откат — вернуть прежнюю область замка.
- **Недельные блоки расписания** увеличивают объём ответа ЕЛК на ≤ 1 неделю — приемлемо (F1).
- **Корзины календаря** могут отдать больше событий, чем нужно; `project` режет, но стоимость
  загрузки растёт до 6 AJAX-страниц — тот же потолок, что и сейчас.
- **Миграция `istudy`** не проверяется вживую (F9).

- Защита общего результата — `Object.freeze` при записи в кэш, а не тип `DeepReadonly` из §4: тип

- Проверка «N параллельных открытий без сессии» выполнена с N = 3.
