## Карта разделов ЕЛК (разведано вживую + скриншоты пользователя 2026-09-15)

Левое меню SmartPoint (уточнено по реальным скриншотам): **Задачи** (`/task`), **Заявки**
(`/claim`), **Каталог сервисов** (`/service`), **Расписание** (`/schedule` — уже покрыто
`elk_get_schedule`), **Центр сервиса «Студент»** (`/student-services`), **Вопросы-ответы**
(`/faq`), **Выразительная кнопка** (виджет обратной связи), **Моё ДПО** (раскрывающийся пункт,
см. отдельно ниже). Наверху — счётчики (избранное, задачи, «корзина» сервисов), поиск, колокольчик
уведомлений.

### «Заявки» — это реестр с историей, а не форма (важное уточнение)

`/claim` — не просто «подать обращение», а полноценный список ВСЕХ поданных заявок с фильтрами
(Все / В работе / Завершённые), поиском по названию/номеру/автору, фильтром по сервису и периоду
дат. Колонки: Номер, Создана, Содержание, Сервис, Автор, Статус. Реальные примеры из аккаунта:
- `302930` — «Посмотреть форму заявки», сервис «Сервис Студент (studservice)», статус
  **Выполнено**
- `2520447` — «Заявка на сбор данных о воинском учёте», статус **На проверке**

Это подтверждает, что `str-graphql` (или отдельный REST) отдаёт список заявок пользователя —
отличный кандидат на `elk_list_requests` (read-only, высокая ценность, статусы заявок часто
нужно проверять вручную).

### «Каталог сервисов» (`/service`) — рубрикатор всех сервисов ЕЛК

Категории (вкладки): Актуально · Центр сервиса «Студент» · **Я — Студент** · ЭКСТРА · Горячая
линия по цифровым сервисам (ИТ) · **Оцени свои курсы** (это и есть СОП/СОКУОП, ранее было
низким приоритетом — теперь видно, что это отдельный именованный сервис) · Отправка данных
воинского учёта (сервис для обучающихся) · Административные сервисы · Образование и обучение ·
Социальные сервисы · Научные сервисы · Расписание занятий и аудитории · Мероприятия (значит,
афиша мероприятий ЕСТЬ прямо в ЕЛК, не только на online.hse.ru!) · Я – абитуриент.

Популярные сервисы на главной каталога: **Проверка работы в системе Антиплагиат** (прямая
отправка на антиплагиат-проверку — не через отдельную «систему LMS», как я предполагал раньше, а
сервис в самом каталоге ЕЛК), **Ярмарка проектов (Для студентов)**, **SmartPro. Ярмарка ЭПП**
(ярмарка элементов практической подготовки — курсовые/проекты/практики).

### Поиск по ЕЛК — ключевая находка для покрытия «максимума»

Строка поиска в шапке ищет не только по интерфейсу, а по **254 сервисам** сразу (плюс
сотрудники/студенты/подразделения отдельными вкладками со своими счётчиками). Это подтверждает,
что ЕЛК — единая точка входа буквально во ВСЕ административные сервисы ВШЭ, и что для «максимума
покрытия» выгоднее реверс-инжинирить ЭТОТ поиск (один API → доступ к сотням сервисов), чем гадать
и разведывать каждый сервис по отдельности. **Это самая высокая по ROI следующая задача.**

Реальные сервисы, найденные по запросу «заявка» (это лишь часть от 254):
- Подать заявку на практику / Заявки на практику (стажировки)
- Подать заявку на внеакадемическую мобильность
- Международная академическая мобильность (отдельный сервис от внеакадемической)
- Подать заявку в комиссии студенческого совета
- **Стипендии** — «Заявка на стипендию, в том числе повышенную и социальную» — **опровергает**
  более раннее предположение «заявку подавать не нужно»: как минимум для повышенной/социальной
  стипендии в ЕЛК есть цифровая форма подачи
- Запись на консультацию к психологам

### «Моё ДПО» — отдельный модуль допобразования

Раскрывающийся пункт левого меню, подпункты: Мои события, Каталог программ, Рекомендации, Мои
программы, Мои документы, Оформить заказ, История просмотров, Поддержка ДПО. Это весь жизненный
цикл доп. проф. образования (курсы повышения квалификации и т.п.) — релевантно, если студент
проходит программы ДПО помимо основной.

## Сделано (2026-09-15, продолжение)

- [x] **`elk_search_services(query)`** — реверс-инжинирен и реализован. Эндпоинт:
      `GET lk.hse.ru/api/search/search-all?query=<q>&offset=0&limit=<n>&category=services`,
      авторизация тем же `Authorization: Bearer <access_token>` из localStorage, что и у
      остальных `elk_get_*`. Ответ: `{total_hits, categories: {services: N, ...}, data: [{score,
      data: {id, name, desc, url}}]}` — `categories` считает совпадения по ВСЕМ категориям
      (сотрудники/студенты/сервисы/подразделения) независимо от фильтра `category`, так что по
      нему видно, есть ли смысл искать ещё и людей/подразделения (отдельный `category=employees`
      и т.п. не реализован — фильтр в UI недоступен для категорий с нулём совпадений, не
      проверено вживую). Проверено на реальном аккаунте: запрос «справка» → 263 совпадения,
      «заявка» → 254.
      **Побочная находка**: URL сервисов заказа справок имеют вид
      `student-service/student-service-first?components=<id>` (напр. `...?components=14605` для
      справки о подтверждении факта обучения) — подсказка для следующей задачи (разведка формы
      заказа справки).

- [x] **`elk_list_requests`** — реверс-инжинирен и реализован. Эндпоинт:
      `GET lk.hse.ru/api/claims?username=<email>&limit=<n>&sort_by=created&order_by=desc` — в
      отличие от большинства elk_* эндпоинтов требует email явным query-параметром (не берётся
      из токена). Поле `url` в сырых данных приходит с нестрипнутым хвостом вида `...GUID=...
      </link><display>Форма</display></hyperlink>` (похоже, source — Camunda/BPM отдаёт
      rich-text без санитизации) — тул обрезает по первому `<`. Проверено на реальном аккаунте:
      1 заявка («Заявка на сбор данных о воинском учёте», статус «На проверке»).

- [x] **`istudy_get_report` / `istudy_get_exams`** — новый сервис `src/services/istudy/`.
      istudy.hse.ru — REST API (не GraphQL), но не «прямой» fetch с Bearer/cookie: авторизация
      SPA держится на токене в памяти приложения, поэтому собственный `fetch({credentials:
      "include"})` с любым путём получал 401 (даже `/api/user/active-role`), несмотря на то, что
      те же URL при обычной загрузке страницы отвечали 200. Решение — не повторять запросы
      вручную, а слушать `page.on("response")` и забирать уже готовые ответы, которые SPA сама
      шлёт при заходе по SSO-ссылке (`/api/student/<numericId>/{profile,report-info,rating,
      exams-by-period}`); `numericId` (studentId) отличается от `lpvGuid` и виден только в URL
      после редиректа на `/gradebook/student/<id>`. Проверено на реальном аккаунте: профиль,
      report-info (приказ о зачислении, направление), rating (пока нули — 1 курс без сданных
      модулей) и список из 26 дисциплин с оценками/зачётами за текущий период.

## Учёба
- [ ] **Проверка работы в системе Антиплагиат** [НОВОЕ, подтверждено] — прямой сервис в каталоге
      ЕЛК (`/service`, категория «Актуально»/популярные), НЕ через отдельную «систему LMS», как
      предполагалось раньше
- [ ] **«Оцени свои курсы»** [НОВОЕ, подтверждено] — это и есть СОП/СОКУОП, оказался отдельным
      именованным сервисом в каталоге, а не просто «раз в модуль» активностью без конкретного URL
- [ ] **Заказ справок как write-тул** (`elk_order_certificate`) [РАЗВЕДАНО 2026-09-15, не
      реализовано] — по клику на кнопку справки на `/student-services` открывается
      `/student-service/student-service-first?components=<id>` (id найден через
      `elk_search_services`, напр. 14605 — справка о подтверждении факта обучения). Это НЕ
      отдельная форма на справку, а один общий Formily-based конструктор форм (низкокодовый
      рендерер схем, ~190KB JSON на все сервисы `/student-services` сразу): `GET
      /api/formily/get-form?slug=student-service-first` отдаёт JSON-схему полей, `GET
      /api/form-access/check?slug=...&components=<id>` проверяет доступ, `GET
      /mdm-gate/elk/get-person-education-info` подтягивает автозаполнение из личных данных, три
      запроса `POST /api/str-graphql` тянут CMS-контент (Strapi GraphQL — см. пункт про
      `/api/str-graphql` в «Техническом долге») для текста/условий конкретной справки по
      `components`. Поля формы названы `jira_customfield_NNNNN` — сильный
      сигнал, что submit в итоге уходит в тот же Jira Service Desk, что и хелpдеск-тикеты
      (`pmo.hse.ru/servicedesk/...`), но сам submit-запрос НЕ пойман — сознательно не доводил до
      реальной отправки справки (создаёт настоящую заявку в системе ВШЭ). Полноценный
      `elk_order_certificate` — отдельная объёмная задача: нужно (1) понять маппинг
      `components=<id>` → какие поля Formily-схемы реально показываются/обязательны для этой
      справки (схема общая на все сервисы, конкретный набор определяется `x-reactions` по
      `components`), (2) поймать сам submit-эндпоинт и формат payload — безопаснее всего это
      сделать с согласия и в присутствии пользователя, а не автономно.
- [ ] **Ярмарка проектов / SmartPro Ярмарка ЭПП** [НОВОЕ, подтверждено] — сервисы каталога для
      выбора курсовых/проектных тем и элементов практической подготовки
- [ ] **Практика/стажировки** [НОВОЕ, подтверждено] — «Подать заявку на практику», «Заявки на
      практику» (просмотр статуса, выбор руководителя)
- [ ] **Академическая мобильность** [НОВОЕ, подтверждено] — два отдельных сервиса: «Подать заявку
      на внеакадемическую мобильность» и «Международная академическая мобильность»
- [ ] **portfolio.hse.ru** [подтверждено, отдельный логин] — электронное портфолио (баллы за

## Как двигаться дальше

Самый высокий ROI сейчас — повторить приём «открыть страницу → посмотреть network requests →
найти `Authorization: Bearer` + JSON-эндпоинт» для: (1) кнопки заказа конкретной справки на
`/student-services`, (2) istudy.hse.ru после перехода по lpvGuid-ссылке, (3) содержимого
`/claim` и `/task`. Это тот же самый приём, что уже дал `elk_get_schedule` — если пойти этим же
путём ещё 3 раза, покрытие вырастет резко.
