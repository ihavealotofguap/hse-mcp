# hsemcp — Требования

Назначение и функциональные требования проекта. Технические детали реализации/разведки — в
`docs/recon.md`, статус готовности — в истории коммитов.

## Назначение

Локальный MCP-сервер (stdio), дающий Claude доступ к личной студенческой инфраструктуре НИУ ВШЭ
одного пользователя: расписание, учебные материалы, оценки/зачётка, административные сервисы
личного кабинета, почта. Работает как персональный инструмент через `claude mcp add`, не
предназначен для многопользовательского/серверного развёртывания.

## Целевые системы и способ доступа

| Система | Домен | Способ доступа | Требует |
|---|---|---|---|
| РУЗ (расписание) | `ruz.hse.ru` | Прямой HTTP API, без авторизации | Сеть ВШЭ (Wi-Fi `HSE.Student` / VPN) |
| SmartLMS (Moodle) | `edu.hse.ru` | Playwright + SSO, скрапинг Moodle-страниц | `HSE_EMAIL`/`HSE_PASSWORD` |
| ЕЛК (личный кабинет) | `lk.hse.ru` | Playwright + SSO для логина, далее JSON API с Bearer-токеном из localStorage | `HSE_EMAIL`/`HSE_PASSWORD` |
| istudy (зачётка) | `istudy.hse.ru` | Playwright + SSO-переход из ЕЛК, перехват сетевых ответов SPA | Тот же логин, сессия ЕЛК |
| Почта | `imap.yandex.ru` / `smtp.yandex.ru` | Прямой IMAP/SMTP | `HSE_EMAIL` + `HSE_MAIL_APP_PASSWORD` (обязателен, без fallback на `HSE_PASSWORD`) |

Единый SSO — Keycloak (`saml.hse.ru`, realm `hse`); сессия браузера переиспользуется между
вызовами и сохраняется в `storage/hse-session.json`.

## Функциональные требования

### Реализовано (v1)
1. Поиск людей/групп/аудиторий и получение расписания через РУЗ и/или ЕЛК (два независимых пути,
   т.к. РУЗ недоступен вне кампуса).
2. Просмотр курсов SmartLMS: список курсов (с прогрессом и датами), материалы, задания со
   сроками, оценки, внутренняя почта (переписка с преподавателями, отдельная от корпоративной).
3. Просмотр профиля студента ЕЛК: identity, структурированная академическая карточка
   (`elk_get_academic_data`), расписание.
4. Поиск по каталогу сервисов ЕЛК, просмотр истории поданных заявок (`elk_list_requests`) и
   задач (`elk_list_tasks`).
5. Просмотр детальной зачётки/рейтинга через istudy.hse.ru (точные цифры GPA/percentile, в
   отличие от ЕЛК, где это иногда «—»). **Сейчас недоступно:** данные зачётки за двухфакторным
   подтверждением через MAX, которым пользователь не пользуется (см. п. 11 и спецификацию
   подпроекта 3, §12).
6. Статус проверок в системе Антиплагиат, статус СОП («Оцени свои курсы») и статус ВКР/КР/проекта
   (тема, % заимствований, оценка).
7. Чтение, поиск и отправка почты корпоративного ящика.
8. Открытие произвольной страницы edu.hse.ru / lk.hse.ru как fallback, когда для раздела ещё нет
   специализированного тула (`lms_open_page`, `elk_open_page`) — возвращает текст + ссылки, а не
   структурированные поля, т.к. вёрстка ЕЛК за пределами `/profile` не документирована.
9. Электронное портфолио, заявки на практику, программы ДПО, история заявок на повышенную
   стипендию — все читаются через общий SSO-мост `lms.hse.ru/elk_login.php` без отдельного логина
   portfolio.hse.ru, которого требовало более раннее (ошибочное) предположение.
10. Сводки и планирование одним вызовом (`my_today`, `my_week`, `my_deadlines`): расписание
    (ЕЛК, РУЗ — только запасной), дедлайны SmartLMS из календаря Moodle, окна ЕЛК (СОП), экзамены
    и зачёты, а для `my_today` ещё непрочитанная внутренняя почта SmartLMS, уведомления, активные
    заявки и задачи ЕЛК. Горизонты: сегодня (дедлайны до конца завтра) / 7 дней / `days` (по
    умолчанию 14). Просроченные несданные работы видны во всех трёх тулах, в том числе у
    завершившихся курсов. Корпоративная почта (`mail_*`) в сводки не входит.
11. Что изменилось с прошлого раза (`hse_changes`, `hse_changes_reset`): снимок дедлайнов,
    расписания (на 14 дней), входящего (внутренняя почта SmartLMS, уведомления ЕЛК) и заявок ЕЛК, а по
    явной просьбе (`scopes: ["grades"]`) — оценок журнала LMS; в ответе только изменения (новое,
    изменено, пропало, перенесено, просрочено). Базы по источникам и журнал событий (30 дней, ≤ 500)
    лежат в `storage/changes/state.json`; курсор двигается явным `ack` (`ackSeq` предыдущего ответа),
    поэтому событие не теряется при сбое ответа. Первый запуск источника создаёт базу без событий;
    отказ источника — статус в ответе, а не ошибка. Корпоративная почта (IMAP) источником не
    является. Итоговые и экзаменационные оценки из istudy не входят: данные зачётки закрыты
    двухфакторным подтверждением через MAX, которым пользователь не пользуется. Проверено вживую на
    одном аккаунте (спека подпроекта 3, §18); события `added`/`changed`/`moved` — только имитацией.

### Запланировано (не реализовано)
Плановый проход по бэклогу с оценкой ROI завершён 2026-09-15 — полная разведка каждого пункта в
`docs/recon.md`. Ничего не осталось с понятным путём реализации в read-only режиме; всё
нижеперечисленное попадает в одну из трёх категорий.

**Записывающие операции — требуют `confirm: true` и присутствия пользователя при первом прогоне**
- Сдача домашних заданий в SmartLMS (`lms_submit_assignment`).
- `elk_order_certificate` — заказ справок через общий Formily-конструктор форм
  `/student-services`. Разведана вся цепочка эндпоинтов, submit сознательно не пойман.
- Подача заявок: на практику/стажировку, международную академическую мобильность и социальную
  стипендию (все три — через `window-lms.hse.ru`, Единое окно), повышенную стипендию.
- Запись на консультацию к психологам и отправка данных воинского учёта — обе ведут на
  BPM-раннер `bpm.hse.ru/Runtime/Runtime/Form/<ИмяФормы>` (третья, отдельная от Formily/Yii,
  форм-система ВШЭ); найдены и задокументированы, submit не разведан.

**Вне скоупа — публичный контент без персонализации**
- `grants.hse.ru`, `studscience.hse.ru`, `career.hse.ru`, `library.hse.ru`, `studlife.hse.ru`,
  `volunteer.hse.ru` — подтверждены обычными CMS-страницами hse.ru, доступными без логина.
  `studsupport.hse.ru` не проверен отдельно, но той же природы по домену/описанию.

**Не реализовано из-за неясного формата запроса**
- История заявок на стипендию через общий DataTables-грид ЕЛК (`?r=st/request/history-dt`) — POST
  сложнее обычного, точные параметры не пойманы. Не критично: `elk_get_scholarship_history`
  покрывает тот же смысл через другой, GET-based эндпоинт того же портала.

**Низкий приоритет, не разведано**
- Остальные разделы модуля ДПО (Мои события, Каталог программ, Рекомендации, Мои документы,
  Оформить заказ, История просмотров, Поддержка ДПО) — только «Мои программы» реализовано.

## Нефункциональные требования

- **Без тестов и линтера по решению проекта** (см. CLAUDE.md) — качество обеспечивается ручной
  проверкой на реальном аккаунте перед фиксацией в docs/recon.md/README.
- **Только для одного пользователя** — учётные данные (`HSE_EMAIL`/`HSE_PASSWORD`,
  `HSE_MAIL_APP_PASSWORD`) хранятся в `.env`, не коммитятся; `storage/` с сессией браузера тоже
  в `.gitignore`.
- **`.env` читается относительно расположения `config.ts`**, а не `process.cwd()`, т.к.
  сторонние хосты (Claude Desktop и т.п.) запускают stdio-сервер с произвольным рабочим
  каталогом.
- **Все внешние вызовы должны идти либо напрямую по HTTP (РУЗ, почта), либо через общий
  Playwright-браузер** (`src/auth/browser-session.ts`) — не создавать отдельные инстансы
  браузера на сервис.
- **Разбор непредсказуемой вёрстки** (ЕЛК за пределами `/profile`) — через `dom-utils.ts`, без
  привязки к CSS-классам (тема ВШЭ кастомизирована и может меняться).
- **Внешние сетевые вызовы (IMAP/SMTP) должны иметь явные таймауты** — не полагаться на
  библиотечные дефолты (минуты), чтобы тул не зависал на неопределённое время при сетевых
  проблемах вместо понятной ошибки.
- **Нагрузка на порталы ВШЭ ограничена**: не больше 3 одновременно открытых страниц общего
  браузера и ≥300 мс между открытиями, прямые API-запросы — не чаще 1 в 100 мс
  (`src/limiter.ts`; пороги не измерены на антибот-защите ВШЭ). Новый код открывает страницы
  только через `withPage` и не вкладывает вызовы друг в друга; слот возвращается по завершении
  вызова либо по дедлайну (45 с).
- **Данные читающих тулов кэшируются в памяти на 2–30 минут** (`src/resource.ts`,
  `src/cache.ts`), кэш на диск не пишется. Свежесть по требованию — `hse_clear_cache`. Любая
  будущая записывающая операция обязана объявлять `invalidates` для затронутых ресурсов и
  никогда сама не кэшируется. Почта и RUZ не кэшируются.
- **Агрегаторы возвращают частичный результат**: отказ или таймаут одного источника не роняет
  сводку и явно отражается в `sources`; таймаут источника 40 с; сам агрегат не кэшируется
  (кэшируются клиентские вызовы под ним) и не использует почту/IMAP.
- **Состояние снимков хранится на диске** (`storage/changes/state.json`, `storage/` в
  `.gitignore`): только нормализованные факты — без токенов, email, ФИО, тел писем, текста
  уведомлений и заявок, url с query. Темы писем и заголовки уведомлений хранятся как есть — принятый
  риск. Хранятся также (в `state.json` и в его копиях `state.json.corrupt-*`): значения оценок,
  названия курсов, элементов оценивания и занятий, аудитории и корпуса, названия сервисов заявок.
  `0o600` на Windows не защита, защищает ACL профиля. Сброс — `hse_changes_reset({ confirm: true })`;
  полный (без `scope`) удаляет и копии `.corrupt-*`, и оставшиеся `*.tmp`, частичный их не трогает.
  Это единственное место, куда проект пишет данные ВШЭ на диск (кроме сессии браузера); кэш ресурсов
  по-прежнему только в памяти.
- **Свежесть по вызову, а не сбросом кэша**: `maxAgeMs` у вызова ресурса (`hse_changes` — 60 с,
  `fresh: true` — 0); `hse_changes` не вызывает `clearCache`.

## Требования к безопасности / осторожности

- Все существующие тулы — **только чтение**. Любая новая **записывающая** операция (сдача
  задания, заказ справки, подача заявки) обязана:
  1. Требовать явный параметр подтверждения (`confirm: true`) в input-схеме — без него тул
     должен возвращать ошибку/описание того, что будет отправлено, не выполняя действие.
  2. Не тестироваться автономно на реальном аккаунте пользователя без его присутствия/согласия —
     см. кейс `elk_order_certificate`, где submit-эндпоинт намеренно не пойман по этой причине.
- `RUZ` работает только из сети ВШЭ — не пытаться обойти это ограничение (прокси, VPN-туннели и
  т.п.) без явного запроса пользователя; текущее решение — `elk_get_schedule` как легитимная
  альтернатива вне кампуса.
- Не логировать и не выводить в коммиты пароли/токены; `.env`, `storage/hse-session.json` уже в
  `.gitignore`.
- Тулы `*_open_page` (SmartLMS/ЕЛК) открывают страницы в общем авторизованном Playwright-браузере
  с активной SSO-сессией ВШЭ — абсолютные URL за пределами allowlist по хосту
  (`src/url-utils.ts#resolveScopedUrl`) должны отклоняться, а не открываться: иначе это
  SSRF-подобная утечка сессии на произвольный внешний домен (усугубляется тем, что эти тулы
  парсят сторонний контент — риск prompt injection).
- Пароль почтового приложения (`HSE_MAIL_APP_PASSWORD`) не должен иметь fallback на
  `HSE_PASSWORD` — секрет единого SSO ВШЭ не должен уходить на серверы стороннего почтового
  провайдера (Яндекс).

## Ограничения (данность, не баги)

- РУЗ недоступен вне сети ВШЭ.
- Селекторы ЕЛК за пределами `/profile` не проверены вживую для всех разделов — `elk_open_page`
  возвращает сырой дамп, а не структурированные поля, пока конкретный раздел не разведан.
- LMS/ЕЛК — только чтение в этой версии.
- Требуется одноразовая настройка окружения: `npm install`, `npx playwright install chromium`,
  заполненный `.env`.
